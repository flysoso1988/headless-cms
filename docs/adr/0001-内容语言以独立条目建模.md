# 内容语言以独立条目建模

同一篇内容在不同语言下的版本是 `vk-cms-content` 里彼此独立的两条记录，不共享 `document_id`，也不提供任何跨语言的关联、对照或「翻译到此语言」入口——因为本次多语言功能只要求「按语言录入与筛选」，引入翻译组会让删除、发布、字段同步的语义全部变成跨条目的联合决策。

## Considered Options

- 沿用 `document_id` 作为语言版本分组键（列表显示另一语言是否已存在、新增译文时预填源内容）：被否，属于另一轮 feature。
- 编辑时允许改语言（等于把条目迁移到另一语言）：被否，语言在创建时确定后不可变。

## Consequences

`admin/cms/content/sys/add.js` 中「document_id 为空时自动生成，用于后续国际化版本关联」这句注释描述的是**未完成的意图**，不是已生效的行为：目前每条内容的 `document_id` 各自独立，与语言无关。读到这句注释不要认为关联机制已经存在，也不要「顺手补上」共享逻辑。

`locale` 为空的历史内容在开启了多语言的模型下，无论选择哪种语言都不会出现在列表里，这是明确接受的范围外事项。
