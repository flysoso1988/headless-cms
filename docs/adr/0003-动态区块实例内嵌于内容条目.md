# 动态区块实例内嵌于内容条目

动态区块（Dynamic Zone）的组件实例数组作为 JSON 数组**内嵌**在所属内容条目文档上（`{ __component, ...字段 }` 逐块堆叠），不落任何独立集合。区块 不要 使用 `vk-components-dynamic`，也不要借用 `document_id` 做实例关联——`document_id` 属于内容语言版本关联的（未完成）语境，见 ADR 0001，两者无关。

## Considered Options

- 每个区块实例落到独立链接表、内容条目仅存 _id 列表：被否。需要额外解决块顺序维护、级联删除、列表聚合三次跨集合读写；MongoDB 文档库没有分表收益；与现有「动态字段平铺在 vk-cms-content」的数据形态不一致。
- 完全不校验区块内部结构，交给前端编辑器自查：被否。绕过编辑器直发脏数据会直接把消费端的按类型渲染全部污染下来；递归一层白名单成本很低，收益高。

## Consequences

- 区块数据**不能跨条目共享**、不能单独鉴权：这是接受的边界，当前场景（文章内嵌推荐商品等）不需要跨条目共享。
- `admin/cms/content` 的写入路径必须对数组做**递归一层白名单过滤**：每块的 `__component` 须在该字段声明允许的组件范围内，块内字段须在该组件模型的字段白名单内。
- 消费端（`pub/getContent` 输出）直接拿到块数组原样 JSON，逐块渲染由 `__component` 驱动。
