# 内容语言与后台界面语言解耦

内容语言（写入 `vk-cms-content.locale`，取值 `zh-Hans` / `en`）描述的是「这条内容是给哪种语言的前台站点看的」，后台界面语言（`locale/lang/*.json`，zh-Hans / zh-Hant / en）描述的是「管理员看到的是中文还是英文的后台」；两套取值恰好同名但毫无关系，因此内容语言的候选清单与默认值硬编码在 `components/cms-content-table/cms-content-table.vue` 里，**不读** `vk.pubfn.getLocale()`，也不跟随后台主题/语言设置变化。

这是刻意偏离显而易见路径的选择：未来读到这段硬编码的工程师很自然会「修好」它，把内容语言接到后台语言上，那会让管理员切换后台界面语言时悄悄改变新建内容的归属语言。同理，语言下拉不提供清空（`el-select` 默认不可清空），是为了排除「无语言」这第三种状态——它等价于一个未被承认的「全部语言」选项，并会让此状态下新增的内容不带 `locale`。

## Consequences

语言清单目前只覆盖集合类型的内容列表；单页类型（`type === 'single'`）即使模型开了 `internationalization` 也不生效，这是本轮明确不做的范围，模型编辑弹窗里的开关保持对所有类型可见，不用 UI 去堵。等语言清单要扩展成模型级或站点级配置时，再把这份硬编码抽到配置层。
